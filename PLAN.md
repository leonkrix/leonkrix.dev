### 4.2 Root Cause (logic puzzle in the style of a murder mystery book)

Our own puzzles for a placement-and-deduction game. **The rules, the full clue catalog, the design decisions and the measurements live in `src/games/root-cause/README.md`; that file is the source of truth, this plan only keeps the summary.**

- **Board and people:** a square N by N map (4 by 4 up to 9 by 9), N people (N minus 1 suspects and one victim), exactly one person in every row and every column. Shapes other than squares come later.
- **Rooms:** connected, at least 2 cells, compact; at most one corridor (a strip) per map. The number of rooms has a lower limit and a generous upper limit per size; the tier only leans (easy more rooms, hard fewer). Every room has a **type and a name** that fit the skin (several of a type allowed, numbered then); clues can speak about a type. The culprit is the suspect who is alone with the victim in a room.
- **Objects and windows:** occupiable objects (landmarks to stand on) and blocking objects, chosen to fit the room. Easy maps have more places to stand and more blocked cells (less free space, so it is clearer where people can be), hard maps have more open floor. Windows sit on walls (board edge or room boundary).
- **People:** Case file gives every person a random first name (never two the same, unique initials for the notes) and a job as role; Outage numbers devices (`sw-01`, `sw-02`, `fw-01`), the victim is a server, a database, a NAS or another device that no suspect shares a type with (`srv-01`, `db-01`), in Case file a founder, CEO, developer and so on (the plan sets the victim per level). Names and labels are unique within every level (tested, also for generated levels).
- **Clues:** rare, as few as needed, every suspect has at least one, **the victim never gets a clue and is never named**, kinds are mixed (no kind dominates, also on hard levels). About 45 types in three levels: about one suspect, combinations (and, or) and **neutral clues about the whole map** (0 to 3 per level, only where needed). Easy levels use level 1, medium 1 and 2, hard all three. "Next to" means the four neighbors inside the same room, a wall is the board edge or a room boundary. **Play-testing decides which types stay**, each type can be dropped in one list.
- **Marking:** the player places a person in a cell, crosses cells out, and writes **notes**: small, faint initials of the people who could be there, several per cell; a switch changes between place, note and cross mode. There is no instant feedback; the game recognizes a solution only when every person is placed correctly, then the culprit is revealed.
- **Skins** (one engine, two looks, both are built, decided by Leon on 2026-10-08): **Case file** (our own detectives, suspects and rooms in tech settings: server room, open office, break room) and **Outage** (network version: rooms are network zones, the victim is the failed device, for example always a server, the suspects are devices such as router, switch, firewall and NAS, and the root cause is the device that is alone with the failed one in a zone). ### 4.4 Link Up (grouping game, Connections style)

Sixteen terms, find the four groups of four. Unlimited random puzzles from a **pool of about 240 categories with more than 3,000 terms** (own data written for this game, `src/games/link-up/data/`, 7 to 20 terms per category: sorting algorithms, HTTP methods, databases, Git commands, protocols, ML models, Linux commands, fonts, Android versions, hardware and so on; the data is split in files and only those of the four categories of a puzzle are fetched). Every term belongs to exactly one category, a `conflicts` list keeps categories apart whose terms could be mistaken for each other (HTTP DELETE is also SQL), and the generator checks every puzzle with a separate solution counter (exactly one solution), the same idea as the solver of Root Cause. Four mistakes allowed.

Decisions (2026-10-12): the fourth pick hands the group in by itself (no Submit button); "One away!" hint when three of four are right (still a mistake); the same wrong group again is free; the definition of a term shows under the board on hover, focus or tap; categories are only revealed once a group is found (or lost); a lost game reveals the missing groups one by one; the link of a puzzle (`?seed=`) opens the same puzzle.

- [x] Data and generator with tests (no ambiguity, pool size, every category documented), UI with slide, shake, hop and reveal animations, keyboard play, e2e, axe, README
- [x] Budget measured and set (`GAME_BUDGETS`), the game is `live` in the registry
- [x] **Built, played and live (2026-10-12).** About 240 categories with more than 3,000 terms (7 to 20 each, own work, no filler; only fitting terms, a topic may stay small), found by going through the Tech Words lists and by topic: algorithms and theory, languages and frameworks, software engineering, the web, data and cloud, networking and security, Linux and operating systems, hardware, machine learning and AI, people. The data is split into 14 files and a catalog (generated by a test, `-u` updates it), a puzzle fetches only the files of its four categories, and a small script of the page starts the first puzzle while React loads (Lighthouse 96 on the game page, scripts about 110 KB). ### 4.5 Network game: Backbone (built 2026-10-18, merged 2026-10-20)

Decided with Leon on 2026-10-17 (the whole concept is in [docs/network-game-concept.md](docs/network-game-concept.md), the rules and design decisions in [src/games/backbone/README.md](src/games/backbone/README.md)): a **planning game that a simulation judges**. A level is a network, flows with service profiles (voice, control, transaction, video, web, bulk) and one to three situations. The player draws paths, a deterministic stress test runs the plan, an exact solver has proven the best plan before the level is shown. Stars compare the plan with shortest path, load balanced and the best plan. A fixed campaign of 13 chapters (one new rule each: capacity, sharing, splitting, latency, priorities, queues, failures and backup paths, building under a budget, loss and redundancy, moving links, zones and a firewall, an attack, everything) with 78 levels (six per chapter), plus random levels in five tiers made in background threads. Absolute score (100 is everything delivered in time; the first four chapters only admit levels whose best plan is perfect or nearly), best plan shown only after a level is solved, helpers (shortest for all, balanced) that earn no stars.

- **Decided with Leon on 2026-10-18 (after the first look):** a new chapter **Queues** (finite buffers with a backlog that carries over from step to step; bursts are absorbed at the price of waiting time, a full buffer drops), a chapter **Under attack** (a flood from one node to another that a firewall filters), **hints** with an explanation, and **six levels per chapter** (13 chapters, 78 levels).
